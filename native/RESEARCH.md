# C++ version: research

Started 2026-11-01, measured against the browser game at v0.1.35. Nothing here is built yet.

## The short answer
It can be done, and it can be a normal `.exe` on Steam. But it is a rewrite of the whole game, not a conversion. No tool turns this code into C++, so every part gets rewritten by hand and checked against the browser game.

Hollow Knight was built in Unity with C#, using the PlayMaker tool for its enemies, so it isn't a C++ template to copy. What carries over is the result: a real `.exe`, smooth frame rate and instant input.

## What has to be rebuilt
Measured from `game/Wallfall.html`.

| Part | Size in the game | Difficulty |
|---|---|---|
| Game logic | 7,531 lines, 44 sections, 25 classes | Large, but direct to translate |
| Drawing | 753 `fillRect` and about 700 other drawing calls, 51 gradients, 5 blend modes, 43 text draws | Medium, solved by one shared layer |
| Sound | All generated by code: oscillators, 34 gain nodes, a filter, a reverb, a compressor. No sound files | Medium, with a risk of sounding different |
| Menus | 225 lines of web styling, 12 inline SVG images, HTML dialogs, typed conversations | **Largest job for looks.** C++ has no web styling, so each screen is redrawn by hand |
| Saves | Browser storage | Small: real files, synced by Steam Cloud |
| Co-op | Relay server, WebSocket messages | Medium, see the decision below |
| Accounts | Server login | Probably not needed on Steam, because Steam Cloud does that job |

## Recommended tools
- **SDL3** for the window, keyboard, controllers and sound output. It is stable (3.4 series) and handles controller hot-plug, button labels and rumble. Steam games must call `SteamAPI_InitEx()` before `SDL_Init()`.
- **Skia** for drawing. It is the graphics engine behind Chrome's canvas, so it is the best chance of matching the look. The risk is that it is known to be awkward to build on Windows, so it gets tested first. If it won't build cleanly, **ThorVG** is the fallback, at the cost of a less exact match.
- **Own sound layer**, modelled on browser audio nodes. **LabSound** came out of WebKit's audio code and is the first thing to try, but it deliberately differs from the browser standard in places, so it has to be checked by comparing recordings.
- **Steamworks SDK** for achievements, overlay, Steam Cloud, invites and networking. App ID 480 (Spacewar) is Valve's sample app.
- **Visual Studio 2026 and CMake**, which are already installed and were tested: a small C++ program built and ran here on 2026-11-01.

## Keeping the look and feel the same
1. **A C++ `Canvas` class with the same calls as the browser's** (`fillRect`, `arc`, `createRadialGradient` and so on), so drawing code can move across almost line for line. The sound layer works the same way.
2. **The same fixed 60 updates a second** as the browser game. The feel comes from running the same maths at the same rate, so it does not change on a 144 Hz screen.
3. **Automatic comparison.** Run both versions with the same recorded inputs, then compare game state each frame and screenshots. The Chrome test tools already exist. The game calls `Math.random` in 78 places, so the tests need a fixed random seed.

Expect a very close match, not a perfect one. Text edges and sound may differ slightly.

## Making changes just as easy
- Rooms, classes, enemy numbers, dialogue and shop prices go in plain data files that reload while the game runs, with no rebuild.
- Those files are generated from `game/Wallfall.html` by a script, so a lot of new content comes across automatically.
- Everything else needs a rebuild, one command taking seconds once set up.
- The honest limit: a new mechanic in the browser game has to be written again in C++. So the two versions drift apart until that is done. `native/PORTED_VERSION` will record which browser version this one matches.

## Order of work
1. **Proof first:** a window drawing with Skia, playing a test sound, reading a controller. If this fails, the plan changes before much work is lost.
2. `Canvas` and sound layers, tested against Chrome.
3. Core loop, player and one room, feeling identical side by side.
4. All rooms, enemies, classes, skills and bosses.
5. Menus, cutscenes, map and conversations.
6. Saves, Steam features and co-op.
7. Full comparison pass, then a Steam build.

## Decisions for the humans
- **Public code:** this folder is in a public repo, so the C++ version is public too, and `package.json` says MIT. If the Steam version will be sold, it should move to a private repo before much is written.
- **Co-op:** Steam's own relay is free, hides IP addresses and needs no server, but Steam players could then only play with Steam players. Keeping the Railway server lets them play with web players, but the server has to stay up. Recommendation: Steam's relay.
- **Freeze point:** porting a moving target is slower, so at some point it helps to pause new mechanics in the browser game while the C++ version catches up.

## Machine notes
Windows 11, RTX 4060 Ti, Visual Studio 2022 and 2026, CMake 4.3, Ninja. The C: drive is 95% full with about 50 GB free, and a Skia build can take a lot of that, so check space first.
